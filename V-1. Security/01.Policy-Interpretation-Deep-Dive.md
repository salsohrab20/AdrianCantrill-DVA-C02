# Policy Interpretation Deep Dive

## Overview

In this three part series, we will step through some IAM policy examples and learn how to interpret them, and understand their effects.

### Steps to follow -
1. Identify the number of statements in the block.
2. Find the effect.
3. Follow Deny(Explicit) - Allow(Explicit) - Deny(Implicit) Policy.
4. Take note of actions or the inverse of each component in document.

## Policies

- **policy1_holidaygifts.json**
```json
{
    "Version": "2012-10-17",
    "Statement": 
    [
      {
        "Effect":"Allow",
        "Action":[
           "s3:PutObject",
           "s3:PutObjectAcl",
           "s3:GetObject",
           "s3:GetObjectAcl",
           "s3:DeleteObject"
        ],
        "Resource":"arn:aws:s3:::holidaygifts/*"
      },
      {
        "Effect": "Deny",
        "Action": [
          "s3:GetObject",
          "s3:GetObjectAcl"
        ],
        "Resource":"arn:aws:s3:::holidaygifts/*",
        "Condition": {
            "DateGreaterThan": {"aws:CurrentTime": "2022-12-01T00:00:00Z"},
            "DateLessThan": {"aws:CurrentTime": "2022-12-25T06:00:00Z"}
        }
      }
    ]
}
```
- **policy2_region.json** - In part 2 ... we learn how to restrict the usage of regions via IAM policies and learn about NOT conditions.
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "DenyNonApprovedRegions",
            "Effect": "Deny",
            "NotAction": [
                "cloudfront:*",
                "iam:*",
                "route53:*",
                "support:*"
            ],
            "Resource": "*",
            "Condition": {
                "StringNotEquals": {
                    "aws:RequestedRegion": [
                        "ap-southeast-2",
                        "eu-west-1"
                    ]
                }
            }
        }
    ]
}
```
**cloudfront, iam, route53, support** - global service (takes home at us-east1) 

> NOTE : It is rare to find any policy document with an explicit deny in isolation. In general it always appears in conjunction with an explicit allow as by default everything in AWS follow implicit deny principle if nothing it mentioned.

- **policy3_homefolders.json** - In part 3 ... we learn how to secure S3 based home folders and IAM policy variables
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:ListAllMyBuckets",
                "s3:GetBucketLocation"
            ],
            "Resource": "*"
        },
        {
            "Effect": "Allow",
            "Action": "s3:ListBucket",
            "Resource": "arn:aws:s3:::cl-animals4life",
            "Condition": {
                "StringLike": {
                    "s3:prefix": [
                        "",
                        "home/",
                        "home/${aws:username}/*"
                    ]
                }
            }
        },
        {
            "Effect": "Allow",
            "Action": "s3:*",
            "Resource": [
                "arn:aws:s3:::cl-animals4life/home/${aws:username}",
                "arn:aws:s3:::cl-animals4life/home/${aws:username}/*"
            ]
        }
    ]
}
```

> NOTE : **s3:ListAllMyBuckets, s3:GetBucketLocation, s3:CreateBucket** - For these three actions we always need to specify * as the Resource
