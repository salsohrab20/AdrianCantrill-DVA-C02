# ⭐ **API Gateway DEMO – Regional API, Resources & GET Methods**

This demo walks through how to **create a Regional API**, add **two resources**, and configure **two GET methods**, each connected to a **Lambda integration**.

---

## **1️⃣ Create a Regional API**

* In API Gateway, choose **Create API → REST API → Build**.
* Set the **Endpoint Type = Regional** (meaning the API is served from the selected AWS Region).
* Name your API and create it.

---

## **2️⃣ Create Two Resources**

You will add resources that represent two different endpoints:

* Resource 1:

  ```
  /
  ```
* Resource 2:

  ```
  /listcats
  ```

Each resource becomes part of the API URL structure.

---

## **3️⃣ Add GET Methods to Each Resource**

For both `/` and `/listcats`:

* Choose **Create Method → GET**
* This method defines the action clients can perform.

---

## **4️⃣ Integrate Each GET Method With a Lambda Function**

For each GET:

* Select **Lambda Proxy Integration = true**
* Choose the corresponding Lambda function:

    * GET /cats → `ListCatsFunction`
    * GET /dogs → `ListDogsFunction`

The Lambda functions handle returning:

* HTTP status codes
* Response body
* Headers

---

## **5️⃣ Deploy the API**

* Choose **Deploy API**
* Create or select a stage (e.g., `dev`)
* After deployment, each endpoint will get an invoke URL:

Example:

```
https://api-id.execute-api.region.amazonaws.com/dev/
https://api-id.execute-api.region.amazonaws.com/dev/listcats
```

---

## ⭐ **Result of the Demo**

You now have:

* A **Regional REST API**
* Two resources: `/` and `/listcats`
* Two GET methods
* Two Lambda integrations
* A deployed, callable API
