# Lambda Aliases and Versions

## Overview

## 1. Big picture: what are versions and aliases?

* **Version** = *Immutable snapshot* of your Lambda code + config (runtime, env vars, timeout, layers, etc).

    * Named like `1`, `2`, `3`, ... plus a special one: `$LATEST`.
    * **$LATEST** is always your *editable* draft.

* **Alias** = *Stable pointer* to a version.

    * e.g. `dev`, `test`, `prod`.
    * Your clients (API Gateway, SQS, other services) call `my-function:prod` instead of `my-function:$LATEST`.
    * You can later point `prod` from version `3` → `4` without changing any integrations.

Think:
**Develop on `$LATEST` → publish version → point alias to that version.**

---

## 2. Prerequisites

You should already have:

* A Lambda function created (e.g. `bestanimal`).
* Basic IAM permissions to:

    * Update the Lambda
    * Publish versions
    * Manage aliases

---

## 3. Step-by-step in AWS Console

### Step 3.1: Update your `$LATEST` code

1. Go to **AWS Console → Lambda**.
2. Create a function (e.g. `bestanimal`) , runtime as python3.14.
3. Open your function (e.g. `bestanimal`) and paste below in code source.
```python
import json

def lambda_handler(event, context):
  #VERSION 1
  print ('Accessing Knowledge.....')
  print ('Cats are the best!!!')
  return "Done!!" 
```

4. **Deploy** the code (if using inline editor) so `$LATEST` is updated and TEST.

At this point, `$LATEST` has your new logic, but **no new version exists yet**.

### Step 3.2: Publish a new version

Repeat above steps with the following code so that version 1 of the code comes into picture

```python
import json

def lambda_handler(event, context):
  #VERSION 1 - with version output
  print ('Accessing Knowledge.....')
  print ('Cats are the best!!!')
  return "Code Version 1"
```
Now -

1. In the function’s Lambda page, look for the **“Versions”** or “Publish new version” option:
    * In the console, often:
      **Actions → Publish new version**
2. Click **Publish new version**.
3. Optionally add a **description** like:
   > "cats are the best"
4. Click **Publish**.

AWS will create version `N` (like `1`) with a *freeze* of the current `$LATEST` code + config.

> Important: Once published, version `1` will **never change**. Any future edits go to `$LATEST` and then to new versions (`2`, `3`, …).

5. If clicked on edit code, it takes us back to the unqualified version of code.

```python
import json

def lambda_handler(event, context):
  #VERSION 2
  print ('Accessing Knowledge.....')
  print ('Cats are the best!!!')
  print ('Doggos are also ok...')
  return "Code Version 2"
```
6. Paste above code and deploy it. It would become version 2.

---

### Step 3.3: Create an alias (if you don’t have one yet)

Let’s say you want a `prod` alias:

1. In the same Lambda page, switch to the **“Aliases”** tab.
2. Click **Create alias**.
3. Fill:

    * **Name**: `prod`
    * **Description**: e.g. `Production alias for best animals`
    * **Version**: select the published version you want (e.g. `1`)
4. Click **Create**.

Now you have:

* Version: `1`
* Alias: `prod` pointing to version `1`
* ARN looks like:
  `arn:aws:lambda:region:account-id:function:best-animals-lambda:prod`

Configure **API Gateway / DynamoDB streams / EventBridge / etc** to invoke **this alias** ARN, not `$LATEST`.

---

### Step 3.4: Update an existing alias to a new version

Next time you make changes:

1. Update code/config → deploy → now `$LATEST` has your new changes.
2. Publish new version (e.g. `2`).
3. Go back to **Aliases**.
4. Click on `prod` → **Edit**.
5. Change **Version** from `1` → `2`.
6. Save.

Traffic using `my-cat-adoption-lambda:prod` now runs version `2` instantly, with no integration changes.

---

## 4. Optional: traffic shifting between versions (weighted aliases)

Aliases can **split traffic** between versions (simple canary deployment).

Example: send 10% traffic to new version `4`, keep 90% on `3`.

1. Go to **Aliases → prod → Edit**.
2. Enable **Additional version** or **Routing configuration**.
3. Choose:

    * Primary version: `1` with 90%
    * Additional version: `2` with 10%
4. Save.

Now:

* 90% of invocations → version `3`
* 10% → version `4`
  After testing, you can edit again and move to 100% → `4`.
